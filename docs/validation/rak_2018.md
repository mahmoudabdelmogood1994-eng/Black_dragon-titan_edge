# Retrospective test on a documented bloom: Ras Al Khaimah coast, January 2018

**Why.** All real results so far are "no confirmed bloom". A documented event lets you check that the detector can see one.

**The event.** The UAE Ministry of Climate Change and Environment announced on Wednesday 24 January 2018 that it was monitoring an algal bloom, after a notice from the Ras Al Khaimah Environmental Protection and Development Authority (The National, 24 Jan 2018); fishermen had reported a patch off RAK on the Monday (22 Jan). The ministry described it as **limited**, in unstable patches of mixed species with **relatively low biomass**, and found no harmful species. So this is a **weak, ambiguous** test: a non-detection would not prove the detector fails, and a detection would not prove it works in general.

**How to run** (needs internet; cell 7 of notebook `02_mirfa_hab_monitor_v6`, or a terminal):

```bash
cd src/mirfa_monitor
python3 titan_hab_pipeline.py series --out out_rak2018 --work s2_rak2018 \
  --bbox 55.55 25.50 56.10 26.00 --intake 25.90 55.75 \
  --aoi-name "RAK coast, documented bloom Jan 2018 (validation)" \
  --start 2018-01-15 --end 2018-02-10 --max-cloud 40 --max-scenes 8
# if no scenes are found, add: --collection sentinel-2-c1-l2a
```

The box and the reference point (not an intake) are my choices: **check them on a map** (the point must be at sea and the box must cover the RAK coast). Scenes from 2018 may have different processing baselines; the pipeline detects the reflectance offset per scene.

**How to read the result.**

| Outcome | Meaning |
|---|---|
| Candidates near the reported area on dates around 22–24 Jan, absent before/after | Encouraging; compare the map with the satellite image in the ministry's release |
| No candidates, but scenes were clear | Inconclusive: low-biomass patches may be below the 0.20 threshold or the 20 m clusters; try the sensitivity table in each event JSON |
| No scenes found / mostly cloud | Use another date or collection; the test did not run |
